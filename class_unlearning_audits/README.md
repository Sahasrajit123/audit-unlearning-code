# Auditing Class-Centric Machine Unlearning

Code for empirically auditing the privacy of class-centric machine unlearning on
CIFAR-100. Four unlearning algorithms share one training pipeline, one sweep runner and one
audit stack. Their privacy lower bounds (ε-DP, ρ-zCDP, μ-GDP) are therefore computed the
same way, on the same trained models, and are directly comparable.

| `--unlearn-method` | Paper | Idea |
|---|---|---|
| `delete` | Zhou et al., *Decoupled Distillation to Erase*, CVPR 2025 ([arXiv:2503.23751](https://arxiv.org/abs/2503.23751)) | Mask distillation. A frozen copy of the trained model is the sole teacher; each forget sample's true-class logit is masked to `-inf` before softmax and the student is distilled onto that. Forget set only. |
| `badteacher` | Chundawat et al., *Can Bad Teaching Induce Forgetting?*, AAAI 2023 ([arXiv:2205.08096](https://arxiv.org/abs/2205.08096)) | Gated KD. On retain samples the student follows the trained model (competent teacher); on forget samples it follows a frozen random init (incompetent teacher). |
| `scrub` | Kurmanji et al., *Towards Unbounded Machine Unlearning*, NeurIPS 2023 ([arXiv:2302.09880](https://arxiv.org/abs/2302.09880)) | Min–max distillation. Max-steps ascend the student–teacher KL on the forget set; min-steps descend `γ·CE + α·KL` on the retain set. |
| `scrub_r` | same paper, §3.2 | SCRUB+R. Same trajectory as SCRUB; returns the epoch whose forget error is closest to the final model's error on held-out validation examples of the forget classes. |

All four are ports of the authors' official implementations. Each module in
[unlearning/](unlearning/) carries the citation and an explicit list of every deviation
from the original in its docstring.

## Repository layout

```
configs/        per-method hyperparameter bundles (+ the SCRUB learning-rate variants)
core/           shared infrastructure
  config.py       YAML + CLI resolution shared by both drivers
  data_utils.py   split loading, on-disk cache, per-run forget sampling
  model.py        architectures (tinynet_cifar100 is the one used)
  train.py        training loop and evaluation
  seeding.py      seed derivation and determinism
unlearning/     method registry (__init__.py) + delete.py, badteacher.py, scrub.py
pipeline/       producing sweeps of trained + unlearned models
  train_and_unlearn.py  one run: sample forget -> train -> unlearn
  run_sweep.py          many runs, parallel across GPUs
  split_test_run.py     hold out the last N runs of a sweep as attack targets
  derive_scrub_r.py     SCRUB sweep -> the SCRUB+R sweep it implies
audit/          attacking a sweep and turning the attack into bounds
  audit_utils.py           per-point LLR attack, reference statistics, eps/rho/mu bounds
  cum_runs_eps_lab.py      combinatorial / Chernoff machinery behind the bounds
  run_cumulative_audit.py  audit driver: one attack pass -> all bounds, all k
  eval_checkpoint_accuracy.py  retain/forget/test accuracy of a checkpoint, cached per sweep
  mia_basic.py             loss-based MIA baseline (Kurmanji et al.)
analysis/       LaTeX table generators
  make_comparison_table.py  bounds tables
  make_mia_table.py         MIA baseline tables
scripts/        shell wrappers (run_demo.sh, run_full_audit.sh, wait_and_sweep.sh, rerun_runs.sh)
```

All Python entry points are modules and are run **from the repository root** with
`python -m <package>.<module>`, e.g. `python -m pipeline.run_sweep --help`. Data is
expected under `data/`, sweeps are written under `runs/`, and tables under `tables/`
(all relative to the root, all created on demand).

## Setup

```bash
pip install -r requirements.txt       # Python 3.11, PyTorch 2.5 used for the paper
```

A CUDA GPU is assumed for the full pipeline (one 60-run sweep trains 60 models for 200
epochs each). Every driver accepts `--device cpu` or `--no-cuda` for smoke tests.

## 1. Data: the CIFAR-100 splits

The CIFAR-100 data splits are generated by the scripts in
`certified_unlearning_plus_grad_based_methods/scripts/`, at the top level of this submission. The
same splitting code produces the splits for both codebases. From this repository's root:

```bash
SPLITS=../certified_unlearning_plus_grad_based_methods/scripts

# 1a. Download CIFAR-100 (python version) and write train/test as batch pickles.
#     -> data/cifar100/data_split/cifar100_no_forget/{train,test}/
python $SPLITS/download_cifar100_batches.py --out_dir data/cifar100

# 1b. Carve val / retain / forget out of train, one data point per batch file.
#     -> data/cifar100/data_split/cifar100_bs_1/{train,val,retain,forget,test}/
python $SPLITS/split_cifar100_train.py --data_dir data/cifar100 --batch_size 1
```

`--batch_size 1` is required. Every experiment in this repository uses this split, and
`data/cifar100/data_split/cifar100_bs_1` is the default `--data-dir` of every driver. The
split script's other flags are left at their defaults
(`--val_split 0.1 --forget_fraction 0.1 --seed 1 --split_mode adversarial`). The split is
deterministic, and we verified that these two commands regenerate the paper's split
exactly (every array in every split identical).

How the split is constructed:

1. **Validation.** A random 10% of the 50,000 CIFAR-100 training images (5,000) is held
   out as `val/`. The remaining 45,000 form the training pool.
2. **Forget pool (class-centric).** Whole classes are added greedily until the pool
   reaches 10% of the training pool, i.e. 4,500 points. To hit the target exactly, at most
   one class may be split between forget and retain. With seed 1 this gives 9 whole
   classes (4, 11, 36, 37, 67, 77, 79, 95, 96) plus 347 of the 731 pool images of class 47.
3. **Retain.** The complement: 40,500 points, 90 whole classes plus the other 384 images
   of class 47.
4. **Test.** The standard 10,000-image CIFAR-100 test set, unchanged.

| split | points | files | role |
|---|---|---|---|
| `retain/` | 40,500 | 40,500 | always trained on; used by the retain-side terms of `badteacher` / `scrub` |
| `forget/` | 4,500 | 4,500 | the candidate pool; each run trains on a random half of it |
| `val/` | 5,000 | 5,000 | held out; SCRUB+R's rewind reference and a basic-MIA "out" population |
| `test/` | 10,000 | 79 | reporting only |
| `train/` | 45,000 | 45,000 | retain ∪ forget pool; written by the split script, not read here |

Each `batch_XXXXX.pkl` holds `(images, labels)`: images `(n, 32, 32, 3)` uint8, labels
`(n,)` int64. Each forget file holds exactly one point, and one file is one sampling unit
(see below). For `test/` the file boundaries do not matter (it is only ever loaded whole),
so it keeps the download step's 128-image files. On first load,
[core/data_utils.py](core/data_utils.py) concatenates each split into
`<split_dir>/.cache/<split>.pt`, so later runs do not reopen ~46k small files.

**What each run trains on and forgets.** Per run, `core.data_utils.sample_forget` draws
exactly `round(0.5 · 4500) = 2250` forget files uniformly without replacement (seeded by
`--forget-seed-base + i`). The model is trained on retain ∪ those 2,250 points, and the
unlearning algorithm is asked to forget exactly those 2,250. The chosen indices are
saved as `forget_indices.npy`. The other 2,250 pool points were never trained on and are
the same-distribution "out" population. The audit's task is to tell the two halves apart.

## 2. Training and unlearning

Each run has three stages, all in `pipeline.train_and_unlearn` (one run) or
`pipeline.run_sweep` (many runs in parallel):

1. **Sample the forget set.** Draw 2,250 of the 4,500 forget-pool points (Section 1).
2. **Train** from scratch on retain ∪ sampled forget (42,750 points). This is the
   "original" model, and it is also the teacher for `badteacher`, `scrub` and `scrub_r`.
3. **Unlearn** the sampled forget points from a copy of the trained model with the chosen
   method.

### Hyperparameters and batch sizes

Training is identical for every method:
- **Model:** `tinynet_cifar100` from [core/model.py](core/model.py), a 4-layer CNN
  (64-64-128-128 channels, GroupNorm, global average pooling, linear head).
- **Optimizer:** SGD, lr 2e-2 with cosine annealing, weight decay 5e-4, no momentum.
- **Schedule:** 200 epochs, **batch size 128** (`--batch-size`).

Unlearning, per method (all set in [configs/](configs/)):

| method | epochs | optimizer, lr | batch size | data seen during unlearning |
|---|---|---|---|---|
| `delete` | 20 | SGD (momentum 0.9), 1e-3 | 128 | sampled forget set only |
| `badteacher` | 5 | Adam, 3e-3 | 128 | retain + sampled forget |
| `scrub` | 3 (max-steps in epochs 1–2) | SGD (momentum 0.9, wd 5e-4), 5e-4 | 128 retain (min-step), 512 forget (max-step) | retain + sampled forget |
| `scrub_r` | as `scrub`, then rewound | as `scrub` | as `scrub` | + validation examples of the forget classes (rewind reference) |

The unlearning batch size is `--unlearn-batch-size` (default: `--batch-size`). SCRUB's
forget-set batch size is `--scrub-forget-batch-size`. These batch sizes are unrelated to
the split's `--batch_size 1`, which only sets how many points are stored per file.

### One run

```bash
python -m pipeline.train_and_unlearn --config configs/delete.yaml --unlearn-seed 1 --run-name example
# or configs/badteacher.yaml, configs/scrub.yaml, configs/scrub_r.yaml
```

This writes to `runs/<method>/<run-name>/`:
- `trained_model.pth`, `unlearned_model.pth`: the model before and after unlearning.
- `forget_indices.npy`: which forget-pool points this run trained on and unlearned.
- `metrics.json`: retain / forget / val / test accuracy before and after unlearning, plus
  the per-epoch unlearning history.
- `config.json`: every resolved setting, including seeds.

`scripts/run_demo.sh [method]` is the same thing with training shortened to 60 epochs
and per-epoch evaluation on. It is the quickest way to check an installation.

### A sweep (what the audit consumes)

The audit needs many runs that share the training recipe but differ in which forget
points were sampled. Run 60 per configuration:

```bash
M=delete   # or badteacher, scrub  (scrub_r is derived, see below)
python -m pipeline.run_sweep --config configs/$M.yaml \
    --run-dir runs/$M/cifar100_bs_1 --num-runs 60 --gpus 0,1,2
```

Run *i* (`runs/$M/cifar100_bs_1/run_XX/`) samples its forget set with seed
`--forget-seed-base + i` and unlearns with `--unlearn-seed-base + i`. Training uses the
fixed `--seed`, so a run's trained model depends only on its forget sample.
`--runs-per-gpu` sets how many runs share one GPU. Intermediate unlearning checkpoints
(`unlearned_model_epoch_N.pth`) are saved every `unlearn_checkpoint_every` epochs (set in
each config).

### Sweeps reported in the paper

Every sweep is 60 runs with `--seed 42 --unlearn-seed-base 1000 --forget-seed-base 2000`
(the config defaults), so run *i* has the same trained model and forget sample across all
sweeps. The table generators expect these directory names:

| method | unlearning LR | run dir | `pipeline.run_sweep` arguments |
|---|---|---|---|
| DELETE | 1e-3 | `runs/delete/cifar100_bs_1` | `--config configs/delete.yaml` |
| | 3e-3, 1e-4 | `runs/delete/cifar100_unlearn_lr_{3e-3,1e-4}_bs_1` | `+ --unlearn-lr …` |
| Bad teacher | 3e-3 | `runs/badteacher/cifar100_bs_1` | `--config configs/badteacher.yaml` |
| | 1e-3, 1e-4 | `runs/badteacher/cifar100_unlearn_rate_{1e-3,1e-4}_bs_1` | `+ --unlearn-lr …` |
| SCRUB | 5e-4 | `runs/scrub/cifar100_bs_1` | `--config configs/scrub.yaml` |
| | 3e-3, 1e-3, 1e-4 | `runs/scrub/cifar100_unlearn_lr_{…}_bs_1` | `--config configs/scrub_unlearn_lr_{…}.yaml --reuse-trained-from runs/scrub/cifar100_bs_1` |
| SCRUB+R | all four | `runs/scrub_r/<same name as the SCRUB sweep>` | none: `python -m pipeline.derive_scrub_r --scrub-dir runs/scrub/<sweep>` |

For example, the DELETE sweep at 3e-3:

```bash
python -m pipeline.run_sweep --config configs/delete.yaml --unlearn-lr 3e-3 \
    --run-dir runs/delete/cifar100_unlearn_lr_3e-3_bs_1 --num-runs 60 --gpus 0,1,2
```

`--reuse-trained-from <sweep>` skips training: it copies each run's `trained_model.pth`
from an existing sweep. It refuses unless every training setting and every run's forget
sample match, so a model can never be paired with the wrong forget set. The same flag
works for the DELETE and bad-teacher LR variants.

### SCRUB+R is derived, not re-swept

SCRUB+R does not change SCRUB's trajectory, only which epoch is kept, and SCRUB sweeps
checkpoint every epoch. `pipeline.derive_scrub_r` therefore builds the SCRUB+R sweep from a
finished SCRUB sweep in about a minute:

```bash
python -m pipeline.derive_scrub_r --scrub-dir runs/scrub/cifar100_bs_1   # -> runs/scrub_r/cifar100_bs_1
```

1. It reads each epoch's forget error from `metrics.json`.
2. It evaluates the final model on the class-matched validation subset (the rewind
   reference).
3. It selects the closest epoch and writes a complete sweep directory.

The output is value-identical to a genuinely run `scrub_r` sweep with the same seeds. In a
`scrub_r` sweep, `unlearned_model.pth` is the rewound model, and
`unlearned_model_epoch_N.pth` are the raw SCRUB checkpoints. `--scrub-rewind-tie-break`
(default `earliest`) decides between equally close epochs. This matters only when the
criterion saturates (SCRUB at 3e-3).

## 3. Auditing

Nothing downstream of unlearning knows which method ran: the audit sees a
`trained_model.pth` and an `unlearned_model.pth` per run and nothing else.

```bash
M=delete
DATA=data/cifar100/data_split/cifar100_bs_1

# 1. Hold out the last 10 runs as attack targets (moved to <sweep>/test_run/).
python -m pipeline.split_test_run --run-dir runs/$M/cifar100_bs_1 --num-test 10

# 2. Per-point in/out reference statistics from the remaining 50 (shadow) runs,
#    for both the trained and the unlearned models.
python -m audit.audit_utils --run-dir runs/$M/cifar100_bs_1 \
    --data-dir $DATA --both --device cuda:0

# 3. Cumulative audit: one attack pass over the held-out runs -> eps, rho, mu bounds.
python -m audit.run_cumulative_audit runs/$M/cifar100_bs_1 \
    --data-dir $DATA --device cuda:0 --k 500 1500 \
    --summary-out tables/${M}_audit_summary.json
```

[scripts/run_full_audit.sh](scripts/run_full_audit.sh) runs steps 2–3 over every sweep
under `runs/` and skips reference statistics that already exist (`--dry-run` prints the
commands). Set `PYTHON=` to choose the interpreter used by the shell scripts.

### Basic MIA baseline

`audit.mia_basic` implements the loss-based membership inference attack reported by
Kurmanji et al. (Sec. 5). It gives one attack accuracy per model with no bound attached,
on the scale the unlearning literature reports. Several "out" populations are scored:

- `forget_out`: the half of the forget pool the run did not sample. This is the clean
  comparison, where membership is the only difference between the two sides.
- `test_cm`, `val_cm`: test / validation examples of the forget classes.
- `test`: all test examples. With a class-centric forget set this is class-confounded,
  so it should be read against the `class_only` control reported beside it.

```bash
python -m audit.mia_basic --source unlearned       --device cuda:0 runs/delete/* runs/scrub/* runs/scrub_r/*
python -m audit.mia_basic --source unlearn_epoch_1 --device cuda:0 runs/badteacher/*
python -m audit.mia_basic --source trained         --device cuda:0 runs/*/*
```

### Tables

```bash
python -m analysis.make_comparison_table   # -> tables/lower_bounds_k{500,1500}_{mean,median}.tex
python -m analysis.make_mia_table          # -> tables/mia_basic.tex
```

Each table records the checkpoint source used per method in its header. Bad teacher is
reported at unlearning epoch 1 and the other methods at their final model.

## 4. Configuration

A method is chosen with a config file or a flag, and the two compose:

```bash
python -m pipeline.run_sweep --config configs/delete.yaml --run-dir runs/delete/my_sweep
python -m pipeline.run_sweep --unlearn-method badteacher --run-dir runs/badteacher/my_sweep
python -m pipeline.run_sweep --config configs/delete.yaml --run-dir runs/delete/lr3e-3 --unlearn-lr 3e-3
```

Resolution order, lowest to highest (see [core/config.py](core/config.py)):
1. the argparse default
2. the method's registry `defaults` ([unlearning/\_\_init\_\_.py](unlearning/__init__.py))
3. its `sweep_defaults` (`pipeline.run_sweep` only)
4. the `--config` YAML
5. an explicit CLI flag

The methods' published hyperparameters differ: DELETE uses 20 epochs of SGD+momentum at
1e-3, bad teacher 5 epochs of Adam at 3e-3, and SCRUB 3 epochs of SGD at 5e-4 (2 with a
max-step). For that reason, combining one method's config with another `--unlearn-method`
is an error, not a blend. Unknown YAML keys are also an error.

Method-specific flags (setting one the chosen method does not read prints a warning):

| Flag | Method | Meaning |
|---|---|---|
| `--disable-bn` | `delete` | Freeze BatchNorm running stats during unlearning. |
| `--temperature` | `badteacher` | KL distillation temperature. |
| `--scrub-msteps` | `scrub`, `scrub_r` | Leading epochs that get a max-step (default 2 of 3). |
| `--scrub-alpha` / `--scrub-gamma` | `scrub`, `scrub_r` | Min-step weights on KL-to-teacher and retain CE (0.001 / 0.99). |
| `--scrub-kd-temperature` | `scrub`, `scrub_r` | Distillation temperature (4.0). |
| `--scrub-forget-batch-size` | `scrub`, `scrub_r` | Max-step batch size (512); the min-step uses `--unlearn-batch-size`. |
| `--scrub-optim` / `--scrub-momentum` / `--scrub-weight-decay` | `scrub`, `scrub_r` | Unlearning optimizer (`sgd` / 0.9 / 5e-4). |
| `--scrub-lr-decay-epochs` / `--scrub-lr-decay-rate` | `scrub`, `scrub_r` | Step LR schedule (`3,5,9` / 0.1). |
| `--scrub-rewind-tie-break` | `scrub_r` | `earliest` or `latest` among equally close epochs. |

## 5. Seeding

Training and unlearning are seeded independently, because the audit needs many runs that
differ only in what was forgotten.

- `--seed`: model init and the training set's batch shuffle. Fixed across a sweep.
- `--forget-seed-base`: run *i* samples its forget half with seed `base + i`.
- `--unlearn-seed-base` (sweep) / `--unlearn-seed` (single run): everything inside
  unlearning. Each method derives independent sub-seeds from it via
  `core.seeding.derive_seed`.

A sweep is fully reproducible from `(--seed, --unlearn-seed-base, --forget-seed-base)`.

## 6. Reading the audit output

- `eps_lb` is a certified-unlearning ε at δ = 0. It is already halved from the local-DP
  parameter the test rejects, which is reported as `eps_ldp`.
- `rho_lb` and `mu_lb` are not halved; their reductions carry the factor of 2 inside the
  divergence bound.
- `eps_estimate_*` are forward conversions of `rho_lb` / `mu_lb` onto the ε axis. They
  are estimates, not lower bounds.
- `None` (printed as `0.00` in the tables) means no positive parameter could be rejected.
  Read it as "no violation detected", never as evidence of privacy. `--` in a table means
  "not audited".
- R/F/T (retain / sampled-forget / test accuracy) is printed next to every bound, because
  a model whose utility has collapsed is trivially hard to attack.
